# NailGo: карта реализации

Что реально работает, что работает частично и чего ещё нет — по состоянию на коммит
`61a858d`. Карта сверена с кодом: маршруты взяты из `src/App.tsx`, ручки — из
`apps/api/src/routes/*.ts`, демо-данные найдены поиском по импортам `data/mock`.

Легенда:

- **работает** — данные в базе, действия меняют состояние;
- **частично** — основное на базе, часть экрана демонстрационная (и это видно на экране);
- **не реализовано** — демонстрация или отсутствует.

## 4. Чего нет вообще

- **Отзыв от клиента** — отзывы можно только модерировать; создать после визита нельзя.
- **Ответ мастера на отзыв** и пересчёт рейтинга/числа отзывов в карточке мастера.
- **Перенос записи** — только отмена и создание новой.
- **Избранное** — ни таблицы, ни localStorage, ни кнопки на карточке мастера.
- **Платежи и предоплата**.
- **Доставка сообщений вне приложения**: SMS, push, email.
- **Админка** — роли в базе есть, интерфейса нет.
- **Загрузка фото и портфолио** — нет хранилища файлов.
- **Гео**: координат у мастеров нет, поэтому карта на `/search` — макет.
- **Лимиты и защита**: нет ограничения частоты запросов кода и попыток ввода OTP, нет блокировки по номеру.
- **Журнал** — контент нечем наполнять (нет ни админки, ни ручек).

## 5. Порядок работ

Порядок выбран по зависимостям: сначала то, без чего остальное работает ненадёжно,
затем то, что замыкает главный цикл продукта, потом витрина и внешние интеграции.

1. ~~**Сессия без обрывов.**~~ **Сделано** (`session` в проверках): пара токенов, продление
   с ротацией, сессии по устройству, выход с отзывом, автопродление в клиенте.
2. **Цикл отзывов целиком.** Клиент оставляет отзыв после завершённого визита (только по своей
   записи, один раз) → мастер модерирует → рейтинг и число отзывов мастера пересчитываются
   из опубликованных → карточка и витрина показывают актуальное. Плюс ответ мастера на отзыв.
3. **Перенос записи** клиентом и мастером на свободное окно — с теми же проверками,
   что и создание (часы, выходные, анти-овербукинг), с уведомлением обеим сторонам.
4. **Услуги кабинета на API.** CRUD: создать, изменить цену и длительность, скрыть, удалить.
   Длительность и `active` уже влияют на слоты — после этого кабинет сможет менять их сам.
5. **Избранное.** Таблица (клиент ↔ мастер), кнопка на карточке, страница из базы,
   уведомление клиенту, когда у избранного мастера появляется подходящее окно.
6. **Горящие окна из базы.** Витрина `/last-minute` собирает свободные окна ближайших дней
   из расписаний и записей — вместо демо-офферов.
7. **Профиль и настройки клиента.** Правка имени, сохранение настроек уведомлений,
   удаление аккаунта (мастер уже видит эту кнопку как заглушку).
8. **Гео и карта.** Координаты мастеров, реальная карта на `/search`, фильтр «рядом».
9. **Внешние каналы и деньги**: SMS/push/email-доставка, платежи и предоплата.
10. **Админка и файлы**: управление мастерами и контентом, загрузка фото и портфолио.
11. **Защита**: лимиты на запросы кода и попытки ввода, базовая защита от перебора.

## 6. Как проверяется

```bash
npx tsc --noEmit && npm run build          # фронтенд: типы и сборка
cd apps/api && npx tsc --noEmit && npm run build

cd tools/devcheck && npm install
npm run bundle && npm run routes           # все маршруты отрисовываются
npm run e2e                                # сквозной сценарий клиент ↔ мастер
npm run data                               # цифры кабинета совпадают с API
npm run messages                           # переписка: обе роли, непрочитанные, чужие диалоги
npm run stats                              # статистика, профиль и часы работы
npm run session                            # продление сессии, ротация, выход, автопродление
```

Проверки самодостаточны: каждая начинает со сброса демо-данных и не зависит от прошлых прогонов.
