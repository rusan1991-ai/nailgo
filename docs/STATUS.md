# NailGo: карта реализации

Что реально работает, что работает частично и чего ещё нет — по состоянию на коммит
ветки `arena/933ce1e5-nailgo` (пункты 1–3 закрыты). Карта сверена с кодом: маршруты взяты из `src/App.tsx`, ручки — из
`apps/api/src/routes/*.ts`, демо-данные найдены поиском по импортам `data/mock`.

Легенда:

- **работает** — данные в базе, действия меняют состояние;
- **частично** — основное на базе, часть экрана демонстрационная (и это видно на экране);
- **не реализовано** — демонстрация или отсутствует.

## 1. Кабинет клиента (13 маршрутов)

| Маршрут | Что это | Состояние | Что именно работает / чего нет |
| --- | --- | --- | --- |
| `/login` | Вход | работает | сначала выбор «куда вхожу» — клиент или мастер, затем телефон и код; незарегистрированный номер получает `not_registered` и предложение зарегистрироваться (молча аккаунт не создаётся), чужая роль — `role_mismatch`. Вход ведёт в свой кабинет: клиент — в «Мой профиль», мастер — в `/pro` |
| `/register` | Регистрация | работает | выбор «кем регистрируюсь» (клиент или мастер) и имя; «я мастер» сразу создаёт профиль мастера и открывает кабинет, занятый номер — `already_registered` с переходом на вход |
| `/admin/login` | Вход администратора | работает | отдельная форма, только вход: без выбора роли и без регистрации, на сайте на неё нет ссылок; мастер и клиент получают отказ (`forbidden`), админ попадает в модерацию |
| `/` | Главная | частично | каталог мастеров и услуг из API, выбор города (Санкт-Петербург или Ленинградская область) и карта города с мастерами; «горящие окна» и статьи внизу — демонстрационные |
| `/search` | Карта мастеров | частично | поиск и фильтры по базе (имя, теги, метро), мастера выбранного города — на карте; фильтры-чипы демонстрационные |

| `/account` | Мой профиль | частично | записи из базы по токену, отмена, перенос на свободное окно, вкладки «Предстоящие/Завершённые/Отменённые»; по завершённому визиту можно оставить отзыв (оценка и текст), виден его статус и ответ мастера; имя и телефон только для чтения |
| `/messages` | Сообщения | работает | переписка с мастерами в базе, непрочитанные, ответ мастера приходит уведомлением |
| `/notifications` | Уведомления | работает | лента из базы, отметка прочитанными |
| `/reviews` | Витрина отзывов | работает | опубликованные отзывы из базы со средним баллом и ответами мастеров |
| `/favorites` | Избранное | **готово** | список из базы с ближайшим свободным окном, сердечки на главной, в поиске и на карточке мастера, уведомление об освободившемся окне |
| `/last-minute/:city` | Горящие окна | **готово** | ближайшие свободные окна из базы с фильтром по региону и периоду, запись из карточки |
| `/journal` | Журнал | **не реализовано** | демо-статьи из мока |
| `/settings` | Настройки клиента | **готово** | имя сохраняется в базу и видно мастеру в записях, два переключателя уведомлений реально глушат события записи и предложения об окне, удаление аккаунта с подтверждением словом |

## 3. Ядро: API, база, вход, уведомления, деплой

| Блок | Состояние | Детали |
| --- | --- | --- |
| API | работает | Fastify + Drizzle, 59 ручек под `/api`, ошибки в одном формате (Zod → 400, `BookingError` → 409/404, пустое тело → 400) |
| База | работает | 11 таблиц: `users`, `sessions`, `masters`, `services`, `working_hours`, `bookings`, `reviews`, `notifications`, `otp_codes`, `conversations`, `messages`; миграции в `apps/api/drizzle` (7 штук); отзыв можно привязать к записи (одна запись — один отзыв), у мастера есть город, регион и координаты |
| Локально / на сервере | работает | PGlite (WASM) локально, Postgres на сервере, диалект и миграции одни и те же; прод-образ собирается без PGlite |
| Вход и сессия | работает | OTP по телефону, вход и регистрация — разные экраны: `/login` (выбор кабинета, вход без создания аккаунтов) и `/register` (выбор роли регистрации), у админа отдельная форма `/admin/login` без регистрации; роли `client/master/admin`, свой кабинет у каждой роли, JWT; access-токен 15 минут, refresh — месяц с ротацией (`POST /auth/refresh`), сессии живут по строке на устройство (`sessions`), выход отзывает только свою сессию, клиент продлевает доступ сам при первом 401 |
| Уведомления | частично | в приложении: заявки, подтверждения, отмены, завершения, переносы, сообщения, отзывы (новый отзыв мастеру, публикация и ответ клиенту) — обеим сторонам. SMS, push и email не подключены (провайдеров нет) |
| Демо-данные | работает | `npm run db:reset` локально, `POST /cabinet/demo/reset` в dev; в сидах 4 мастера (три в Санкт-Петербурге, один во Всеволожске), 10 услуг, 21 запись (прошедшие — завершены), 9 отзывов (два привязаны к записям), 3 диалога, аккаунты мастера и администратора |
| Деплой | частично | `Dockerfile.web`, `apps/api/Dockerfile`, `docker-compose.prod.yml` (web, api, postgres), Caddy, скрипты install/update/backup/restore, `DEPLOY.md`. Прод-сборка API проверена против драйвера `pg`; на настоящем сервере не запускалась (в песочнице нет Docker) |
| Проверки | работает | 14 сценариев без браузера — `routes`, `e2e`, `data`, `messages`, `stats`, `session`, `reviews`, `reschedule`, `roles`, `city`, `services`, `favorites`, `last-minute`, `settings-client` (плюс `bundle` пересобирает приложение) + `tsc` фронтенда и API + прод-сборка |

## 4. Чего нет вообще

- **Платежи и предоплата**.
- **Доставка сообщений вне приложения**: SMS, push, email.
- **Админка** — интерфейс пока один раздел (модерация отзывов); управление мастерами и контентом — пункт 10.
- **Загрузка фото и портфолио** — нет хранилища файлов.
- **Лимиты и защита**: нет ограничения частоты запросов кода и попыток ввода OTP, нет блокировки по номеру.
- **Журнал** — контент нечем наполнять (нет ни админки, ни ручек).

## 5. Порядок работ

Порядок выбран по зависимостям: сначала то, без чего остальное работает ненадёжно,
затем то, что замыкает главный цикл продукта, потом витрина и внешние интеграции.

1. ~~**Сессия без обрывов.**~~ **Сделано** (`session` в проверках): пара токенов, продление
   с ротацией, сессии по устройству, выход с отзывом, автопродление в клиенте.
2. ~~**Цикл отзывов целиком.**~~ **Сделано** (`reviews` в проверках): клиент оставляет отзыв после
   завершённого визита (только по своей записи, один раз) → мастер модерирует → рейтинг и число
   отзывов пересчитываются из опубликованных → карточка и витрина показывают актуальное, плюс
   ответ мастера на отзыв.
3. ~~**Перенос записи** клиентом и мастером на свободное окно~~ **Сделано** (`reschedule` в проверках):
   те же проверки, что и при создании (часы, выходные, анти-овербукинг), плюс запрет на чужую,
   отменённую и завершённую запись; обе стороны получают уведомление.
4. ~~**Услуги кабинета на API.**~~ **Сделано** (`services` в проверках): у каждого мастера свой
   прайс (`services.master_id`), CRUD из кабинета — создать, изменить цену и длительность,
   скрыть, удалить; чужие услуги недоступны (403), услугу с записями удалить нельзя
   (409 `service_in_use` → «скройте её»). Слоты и запись принимают только услугу этого мастера
   (404 `service_not_found`), скрытая услуга пропадает из витрины. Кабинет (записи, расписание,
   клиенты, статистика) показывает только своих клиентов.
5. ~~**Избранное.**~~ **Сделано** (`favorites` в проверках): таблица `favorites` (клиент ↔ мастер,
   уникальная пара), сердечки на главной, в поиске и на карточке мастера, `/favorites` из базы
   с ближайшим свободным окном (считается по самой длинной активной услуге — окно подходит под
   любую), уведомление `favorite_slot`, когда окно освободилось (отмена, перенос, открытие дня),
   с антиспамом «не чаще раза в 6 часов».
6. ~~**Горящие окна из базы.**~~ **Сделано** (`last-minute` в проверках): `GET /api/last-minute`
   собирает ближайшие свободные окна из расписаний и занятых записей (общий расчёт `lib/slots.ts`),
   витрина `/last-minute` показывает их с фильтром по региону и периоду, запись — сразу из карточки.
   Каталог с `?windows=1` отдаёт окна карточкам (поиск, страница мастера) вместо демо-времени,
   форма записи перешла на живые даты вместо демо-недели мока.
7. ~~**Профиль и настройки клиента.**~~ **Сделано** (`settings-client` в проверках):
   имя (`PATCH /api/client/profile`) сохраняется и видно мастеру в записях; переключатели
   уведомлений (`PATCH /api/client/settings`) действительно глушат события — выключенные
   «уведомления о записи» не приносят ни создания, ни подтверждения, ни завершения,
   выключенные «акции и окна» — предложений об освободившемся окне; удаление аккаунта
   (`DELETE /api/client/account`, подтверждение словом «УДАЛИТЬ») отменяет будущие визиты,
   обезличивает историю у мастера, убирает избранное, уведомления, переписку и сессии.
8. ~~**Гео и карта.**~~ **Сделано раньше очереди по просьбе пользователя** (`city` в проверках):
   координаты и регион у мастеров, выбор города при входе (Санкт-Петербург и Ленинградская
   область), карта города на главной и на `/search`; без ключа Яндекс.Карт карта работает
   виджетом, с ключом `VITE_YANDEX_MAPS_KEY` — с метками мастеров.
9. ~~**Внешние каналы и деньги.**~~ **Сделано** (`deliveries` и `payments` в проверках):
   *Доставка.* Таблица `deliveries` — очередь сообщений (код входа, заявка, подтверждение,
   напоминание за сутки, отмена, перенос, ответ на отзыв), рассыльщик в API забирает то, чему
   пора уходить, и отправляет транспортом: `log` (запись в журнал — режим стенда), `webhook`
   (POST на адрес любого шлюза) или `smsru` (ключ `SMSRU_API_ID`). Транспорт и адрес переключаются
   в админке на ходу; сбой провайдера не теряет сообщение — «пауза × номер попытки», до трёх
   попыток, потом честный `failed` с текстом ошибки и кнопкой «повторить». Настройки клиента
   (пункт 7) глушат и внешние каналы, а не только уведомления в приложении. Отмена и перенос
   снимают поставленное напоминание и ставят новое.
   *Деньги.* Мастер задаёт предоплату в процентах по услуге; сумма фиксируется в момент записи.
   Запись ждёт оплаты и подтверждается сама, когда деньги пришли. Приём денег — либо у мастера
   (`manual`: перевод или наличные, «я оплатил(а)» от клиента и подтверждение в кабинете), либо
   через платёжный шлюз (`webhook`: мы отправляем операцию, получаем ссылку на оплату, а шлюз
   сообщает об оплате вебхуком `POST /api/payments/webhook`). Отмена оплаченной записи
   возвращает предоплату: клиент видит возврат, мастер и админ — операцию. Раздел админки
   `/admin/payments` показывает сводку (получено, ждём, возвращено, не прошло) и позволяет
   подтвердить или вернуть деньги; повторные вебхуки и повторный возврат ничего не ломают.
10. **Админка и файлы**: управление мастерами и контентом, загрузка фото и портфолио.
    Первый раздел админки — модерация отзывов — уже есть.
11. **Защита**: лимиты на запросы кода и попытки ввода, базовая защита от перебора.

## 6. Как проверяется

```bash
npx tsc --noEmit && npm run build          # фронтенд: типы и сборка
cd apps/api && npx tsc --noEmit && npm run build

cd tools/devcheck && npm install
npm run bundle && npm run routes           # все маршруты отрисовываются
npm run e2e                                # сквозной сценарий клиент ↔ мастер
npm run data                               # цифры кабинета совпадают с API
npm run messages                           # переписка: обе роли, непрочитанные, чужие диалоги
npm run stats                              # статистика, профиль и часы работы
npm run session                            # продление сессии, ротация, выход, автопродление
npm run reviews                            # отзыв клиента, модерация, ответ мастера, рейтинг
npm run reschedule                         # перенос записи клиентом и мастером, правила слота
npm run roles                              # выбор роли при входе, свои кабинеты, доступ в админку
npm run city                               # города, фильтр каталога и карта выбранного региона
npm run services                           # CRUD услуг мастера и влияние прайса на слоты
npm run favorites                          # избранное, сердечки, уведомление об окне и антиспам
npm run last-minute                        # горящие окна из расписаний: занятие, отмена, фильтры
npm run settings-client                    # профиль, уведомления и удаление аккаунта клиента
npm run deliveries                         # очередь доставки, напоминания и повтор после сбоя
npm run payments                           # предоплата: процент, шлюз, подтверждение, возврат
```

Проверки самодостаточны: каждая начинает со сброса демо-данных и не зависит от прошлых прогонов.
